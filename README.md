# DSH Trusted Paths · 可信文件夹引用

为 DeepSeek Harness 工作区设置主目录与可信引用目录。通过侧边栏工作区「…」菜单中的「目录设置」打开浮层，用目录选择器操作，无需手输路径。

> **兼容性提示：本插件依赖定制 Harness 核心扩展，不是可在任意原版 DSH 上直接使用的独立权限补丁。** npm 安装本插件不会修改 Harness 核心。**v0.2.0 提供完整核心补丁、从 v0.1.1 升级的增量补丁和[逐步安装/升级教程](./INSTALL-CORE.md)**，固定上游基线为 `1f81c047fc48fa190a683e469daa699857e9afe8`。不需要自行实现接口，但必须先应用补丁、构建并运行该核心。另见 [COMPATIBILITY.md](./COMPATIBILITY.md)。

## 功能

- 统一目录列表通过 radio 选择唯一主目录（primary），其余为引用目录（ref）；每个已配置工作区必须有一个现存主目录。
- 换主时原主目录保留为引用目录；当前主目录在另设主目录前不可移除。
- 主目录影响该工作区以后新建的会话；已有会话保持原 cwd 与归属，聊天记录不搬家。
- 选择添加目录、逐项移除引用目录；仅点击「保存并授权」后生效。
- 在 `workspace-write` 中通过正式 sandbox policy 扩展可写目录，不关闭沙箱、不全盘信任；`read-only` 不获得写权限。
- 授权仅能由用户操作，不提供模型自行授权的工具。
- 初次安装没有默认可信目录：`workspaces: []`，打开某工作区设置并保存后才产生授权。

**平台范围：本版完整可信授权/撤销实现面向 Windows；Linux/macOS 的对应生命周期接口暂不支持。** 崩溃或未启动的租约可能持续锁定，不能自动恢复，详见兼容性与安装说明。

## 安装

在具备配套接口的 Harness「插件」页面安装 npm 包：

```text
dsh-plugin-trusted-paths@0.2.0
```

或者从仓库下载源码，在 Harness 插件安装入口选择该本地包目录。不要把本插件与旧的 `@local/dsh-trusted-paths` 开发包同时启用，两者使用同一菜单及配置条目标识。旧安装请先备份配置，再在空闲时间迁移。

本包为普通 Cordis bundle：Host 入口、lazy Client module、`dsh.bundle.patch` 和中英显示资源随包发布。不需要额外 Web 服务。

## 使用

1. 打开工作区标题右侧「…」→「目录设置」（在“重命名”上方）。
2. 用「添加目录」打开核心目录选择器，浏览并选择目录加入统一列表。
3. 用 radio 指定唯一主目录；换主后原主保留为引用。不再需要的引用可「移除」，当前主目录须先另设主目录才能移除。
4. 检查路径和授权范围，点击「保存并授权」。取消不会保存草稿。

添加目录复用核心 `directoryBrowser` Client Service。目录浏览支持父级、Host Home、子目录和位置选择；Windows 位置来自真实 Host 的 `GetLogicalDrives`，不逐个探测 26 个盘符。目录来自运行 Harness 的主机，不是远程浏览器所在电脑。

完整补丁含 47 个文件（原有 37 个 + picker 10 个），仍固定同一上游基线。已打 v0.1.1 补丁的 checkout 必须使用 `patches/harness-trusted-paths-0.1.1-to-0.2.0.patch` 增量升级，**不要直接重复应用新版完整补丁**；详见[升级步骤](./INSTALL-CORE.md#7-从-v011-升级到-v020)。

## 安全边界与撤销

- 仅接受绝对路径且目录必须存在；拒绝磁盘根、临时目录重叠和授权控制记录目录重叠。
- 不同工作区的主目录/历史会话目录不能冲突。
- 删除引用不删除文件。停止使用相关目录的命令、终端和子进程后再撤销。
- Windows 不能收回进程已打开的文件句柄；待启动、运行中或异常租约会保守阻止撤销，不会伪报成功。
- 控制记录位于用户主目录 `.dsh-trusted-paths-control`；受限文件工具不能修改。不要删除仍在使用的租约。
- 原始工作区 identity path 与已有会话 cwd 不被改写。历史目录记录用于会话归属，不自动授予写权限。

```sh
npm ci
npm test
npm pack --dry-run
```

测试包含真实 React/RTL/jsdom 浮层交互及 Host 生命周期、目录验证和工作区范围隔离，无需另一个 Harness checkout。平台受限进程与核心集成验证需在配套 Harness 工程中运行，不能用完全权限会话可写外部路径代替验证。

v0.2.0 验证：插件 25 项（16 UI、9 Host）、核心 picker 111 项测试通过；Host、Client、Web 构建均通过，用户实际确认本次三项改动（统一列表/换主规则、复用目录选择器、Home 与真实磁盘位置选择）均正常。先前受限进程写入/拒绝、租约完成/撤销等验证仍属历史记录；本次不宣称完整 suite 全绿，历史 634 通过、1 跳过、1 个 Windows 符号链接 EPERM 失败的限制见安装教程。
